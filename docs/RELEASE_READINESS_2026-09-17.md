# Spooldesk: подготовка первого выпуска

Дата: 17 сентября 2026. Этот документ дополняет [исходный аудит](PROJECT_AUDIT_2026-09-17.md) и фиксирует результат разработки после него. Аудит остаётся историческим снимком, а не описанием текущего кода.

Продолжение: [зависимости, аудит и проверки от 20 сентября](RELEASE_READINESS_2026-09-20.md).
Ниже сохранён исторический статус на 17 сентября; обновлённый набор зависимостей
и результаты его проверки описаны в продолжении.

## Формат первого запуска

Первый выпуск рассчитан на управляемый пилот: отдельный экземпляр, БД, файлы и ключи для каждой организации. Виджет, email, Slack и Telegram — каналы одного helpdesk. Telegram не требуется для работы портала, обработки очередей и SLA.

Публичная регистрация произвольных организаций, общая многопользовательская SaaS-инфраструктура и автоматический биллинг в этот выпуск не входят. Первых клиентов можно подключать вручную по стратегии из [плана продукта](PRODUCT_STRATEGY_2026-09-17.md). Наличие тарифного плана само по себе не подтверждает спрос.

## Что изменилось в коде

| Область | Реализованное поведение |
|---|---|
| Исходящие сообщения | Ответ и задание доставки сохраняются до обращения к провайдеру. Статусы pending/sending/retry/delivered/failed/uncertain/cancelled видны в карточке. Ошибка записи до commit исключает отправку. |
| Повторная отправка | Явный rate limit допускает автоматическую повторную попытку. Неопределённый результат после сетевого сбоя или падения процесса требует решения оператора. Для uncertain интерфейс предупреждает о возможном дубле. Порядок ожидающих ответов внутри тикета сохраняется. |
| Вложения | Исходные байты сохраняются локально до доставки; неудачную отправку можно повторить без повторной загрузки файла. Клиент не видит недоставленные сообщения. |
| Email | IMAP UID/UIDVALIDITY, проверяемый TLS, сохранение raw-письма до Seen, durable обработка и дедупликация. Message-ID/References разделяют темы и сохраняют цепочки ответов. Связи ограничены отправителем и почтовым ящиком. |
| Slack | Событие сохраняется до ACK. Повторное событие не создаёт повторное обращение. Поддержаны file_share, вложения и ответы в исходную ветку. |
| Целостность БД | SQLite всегда проверяет внешние ключи. Уникальны адрес клиента в канале и активный диалог пользователя с conversation_key. Конкурентное создание обращения сериализуется. |
| Обновление схемы | Введены последовательные транзакционные ревизии SQLite/PostgreSQL и таблица schema_migrations. Новая неизвестная ревизия останавливает старую версию приложения. Старые лишние активные диалоги сохраняются под отдельными legacy-ключами. |
| SLA и метрики | Фоновые проверки запускает dashboard без зависимости от bot-процесса. Неудачное уведомление не считается выполненным. Ответ сбрасывает маркер SLA; недоставленные сообщения не считаются ответами; время ответа учитывает delivered_at. |
| Telegram операторов | Права проверяются по активной учётной записи, роли и группе; проверяются callback и FSM. Маршрутизация использует тему, сохранённый reply или явный #ID. Создаётся настоящий forum topic с безопасным переходом на replies. |
| Копии для операторов | Вызовы Telegram вынесены из транзакций записи. Отдельный worker восстанавливает копии по точным ID новых durable заданий; старую историю не пересылает заново. |
| Сессии | Пароль, отключение учётной записи и изменение роли отзывают предыдущие сессии. Logout отзывает текущее поколение сессий оператора. Нельзя удалить/деактивировать последнего активного владельца. |
| AI | Общие gates проверяют включение AI, активность тикета, команду и запретные категории до подготовки контекста и вызова модели. Исправлены привязка черновиков и deflection callback. |
| Widget identity | Подпись v2 охватывает external_id/email/name. Интерфейс показывает только действительно подписанные поля. Старый HMAC подтверждает лишь идентификатор, который подписывался. Непроверяемые старые trust-флаги сброшены миграцией. |
| Виджет | Загрузки файлов последовательно устанавливают сессию; сообщение клиента возвращает waiting в работу. Открытый диалог продолжает получать уведомление о закрытии и CSAT после закрытия. |
| Закрытие и оценка | Статус закрытия и задание уведомления записываются в одной транзакции во всех путях закрытия. Повторное закрытие не создаёт второй запрос оценки; конкурирующие оценки сохраняют первую. |
| Экспорт | Строки XLSX не интерпретируются как формулы; фильтр назначенного оператора сохраняется. |
| Восстановление | SQLite-архив содержит manifest, хеши и локальные вложения. Восстановление только в новый каталог; проверяются целостность БД, ссылки на файлы и безопасные пути. Незавершённые исходящие после restore переходят в uncertain. |
| Эксплуатация | Startup прекращается при ошибке миграции/ключа сессии. /healthz замечает застрявшие очереди. preflight проверяет конфигурацию без сети и вывода секретов. Демо изолировано от реальных credentials и .env. |

## Совместимость и обновление

1. Остановить пишущие процессы; сделать и проверить резервную копию. Сохранить исходный ключ шифрования отдельно. См. [BACKUP_RESTORE.md](BACKUP_RESTORE.md).
2. Прогнать обновление на отдельной копии БД и файлов с отключёнными внешними каналами. Проверить вход владельца, чтение тикетов и вложений.
3. Запустить новую версию. Ревизия выпуска — `20260917_01`. `create_all` создаёт новые таблицы, а revision-функция обновляет существующие колонки и ограничения.
4. Операторы входят заново: cookies прежнего формата больше не принимаются. Клиентские сайты переходят на identity signature v2; старые подписи поддерживаются с ограниченной областью доверия.
5. Откат схемы — восстановление проверенного архива с соответствующей версией приложения. Запуск старого кода поверх новой схемы не является поддержанным откатом.

Миграция не удаляет переписку, чтобы убрать дубликаты. Nullable-ссылки на отсутствующие записи обнуляются. Повреждённые обязательные связи или конфликтующие уникальные идентификаторы требуют исправления копии данных; приложение должно отказаться от небезопасного старта.

## Проверки

Итоговый полный прогон: **1048 passed**, 0 failed, 4169 warnings, 214,48 секунды (`python -m pytest -q --tb=short --disable-warnings`). Предупреждения, включая deprecation зависимостей и datetime.utcnow, не устранены этим выпуском. Python compileall и git diff --check прошли. Локальная среда: Windows, Python 3.13.14, временные SQLite базы. Production image и CI используют Python 3.12; в CI предусмотрены отдельные PostgreSQL и Docker jobs, их выполнение здесь не подтверждено.

Проверки включают конкурентный intake, competing delivery workers, сбои commit до/после внешней отправки, повторение событий, фактическую доставку против pending, отзыв сессий, HMAC, XLSX, миграции и восстановление. Тестам запрещены внешние HTTP/Telegram/SMTP/IMAP обращения; MockTransport и ASGI остаются доступны.

В браузере на изолированном localhost проверены: вход владельца, обращение из виджета, ответ оператора, автоматическое назначение, невидимость внутренней заметки клиенту, выход из waiting после ответа клиента, закрытие, CSAT и сохранение оценки 5/5. Использовались одноразовые данные и отключённые внешние каналы.

Демо создано отдельно во временной папке: 86 тикетов, integrity_check OK. Backup/restore проверен на отдельной БД с реальным запуском инициализации приложения, проверкой Argon2-пароля и расшифровкой ключом, переданным отдельно.

На чистой временной БД также проверен обычный startup без TESTING: применена ревизия, работают четыре фоновых обработчика, исходящий ответ виджета доставлен фоновым обработчиком, /healthz вернул 200. При shutdown все обработчики остановились.

## Что ещё отделяет код от запуска с клиентами

- **Сервер и домен:** выбрать окружение, установить сборку, настроить DNS/TLS, secure cookies и правильное количество доверенных reverse proxies. Не публиковать dashboard напрямую по HTTP.
- **Linux/Docker/PostgreSQL:** выполнить соответствующие CI jobs на окончательном diff. Локально Docker Desktop не запустился; runtime-проверка контейнера и PostgreSQL не подтверждена. Для первого пилота можно выбрать SQLite и не заявлять PostgreSQL проверенным на основании одних SQLite-тестов.
- **Зависимости:** закрепить проверенный набор версий production-сборки и выполнить актуальное сканирование уязвимостей. requirements пока содержит незакреплённые зависимости; локальный pip check и тесты не заменяют эту проверку.
- **Реальные каналы:** провести двусторонний smoke test на выделенном Fastmail/support mailbox, проверить ответы и вложения в той же цепочке. Аналогично проверить только выбранные для пилота Slack/Telegram подключения. Локальные контракты не заменяют настройки сторонних аккаунтов.
- **Recovery rehearsal:** настроить внешнее хранилище и мониторинг свежести backup, восстановить архив на отдельном сервере и измерить время. PostgreSQL backup/restore описан отдельным runbook; SQLite-скрипт не обслуживает PostgreSQL.
- **Операционная готовность:** назначить ответственного за /healthz и failed/uncertain, согласовать расписание поддержки, хранение данных, правила удаления и тексты для клиентов. Массовые рассылки и AI-автоответы включать только после отдельного сценария проверки на выбранном канале.
- **Проверка ценности:** подключить 1–3 организации вручную, измерять время первого ответа, потерянные обращения, частоту использования, готовность платить и трудозатраты на сопровождение. Затем расширять функциональность и тарифы по результатам.

Оставшиеся продуктовые ограничения первого пилота: восстановление пароля и подключение операторов обслуживаются вручную; нет 2FA, общего журнала всех действий, автоматических правил хранения/удаления данных и самостоятельного onboarding компаний. Email пока не имеет кликабельной формы CSAT. Один человек в разных каналах остаётся разными контактами. Эти возможности нельзя обещать как готовые; требования конкретного пилота нужно сверить до подключения. Неограниченные вложения, массовые рассылки и AI-автоответы не входят в исходный объём запуска.

Команда offline-проверки **эффективного окружения** перед запуском:

```bash
python scripts/preflight.py --env-file .env --public-url https://YOUR_SUPPORT_DOMAIN
```

Если Compose задаёт secure cookies/proxy hops поверх `.env`, передавать такие же значения этой команде. `--local` предназначен только для локальной разработки. Preflight не проверяет оплату сервера, DNS, сертификат или доступность почты.

## Ограничения гарантий

SMTP и Telegram не дают универсальной exactly-once доставки: при неопределённом результате портал сохраняет неопределённость. У операторской Telegram-копии возможен повтор при падении после отправки, но до сохранения ID. События/файлы, которые провайдер ещё не передал порталу, зависят от его доступности и срока хранения.

Первый релиз использует общий короткий transaction lock для решений о записи. Это сознательный выбор корректности небольшого отдельного экземпляра; масштаб большой общей SaaS-инсталляции и нагрузочные пределы пока не подтверждены.

**Текущий статус: кандидат для staging и управляемого пилота после перечисленных проверок инфраструктуры. Сам по себе зелёный локальный тестовый прогон не означает готовность публичного SaaS.**

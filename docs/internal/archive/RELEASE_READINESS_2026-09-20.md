# Spooldesk: зависимости и проверка сборки

Обновление к [отчёту от 17 сентября](RELEASE_READINESS_2026-09-17.md).
Формат запуска прежний: отдельный экземпляр для каждой организации,
сначала staging и управляемый пилот. Новые продуктовые функции не добавлялись.

Продолжение: [проверка Linux-контейнера и PostgreSQL](CONTAINER_READINESS_2026-09-20.md).
В продолжении зафиксированы восстановление Docker и результаты реального запуска;
описанная ниже недоступность Docker относится к предыдущему этапу.

## Изменения

- Полные runtime/dev/tooling locks с точными версиями, платформенными условиями
  и SHA-256. Источники — соответствующие `.in`; порядок обновления описан в
  [DEPENDENCIES.md](../../DEPENDENCIES.md).
- aiogram 3.10.0 → 3.31.0 снимает старое ограничение aiohttp 3.9.x.
  Закреплён aiohttp 3.14.3. В старой версии присутствовал, в частности,
  клиентский риск отказа в обслуживании при некорректном ответе сервера:
  [advisory aiohttp](https://github.com/aio-libs/aiohttp/security/advisories/GHSA-cq5v-8q36-5273).
- Аудит исходной `.venv` отметил пять пакетов: aiohttp, anyio, cryptography,
  pip и pyasn1. Новый набор включает anyio 4.15.1, cryptography 50.0.1,
  pip 26.2.1 и pyasn1 0.6.4. Количество сообщений сканера не используется как
  число уникальных проблем: база возвращала дубли некоторых advisory.
- Наличие advisory в библиотеке не доказывает эксплуатацию в Spooldesk.
  Например, найденная проблема cryptography относится к PKCS#7-дешифрованию;
  хранилище секретов проекта использует Fernet:
  [advisory cryptography](https://github.com/pyca/cryptography/security/advisories/GHSA-g6cj-pr64-35w5).
  Пакет всё равно обновлён до исправленной версии.
- Docker устанавливает только готовые wheels с проверкой хешей и выполняет
  `pip check`. Убраны gcc/libffi-dev и незакреплённый `pip install --upgrade pip`.
- CI использует locks, проверяет их повторную генерацию, выполняет аудит app
  и tooling. К Linux-тестам добавлена Windows job на Python 3.12. Существующие
  PostgreSQL, Docker и deployment jobs сохранены. PyYAML для проверки Compose
  теперь устанавливается из runtime-lock, а не берётся из окружения runner.
- Обновлена фикстура `ChatFullInfo`: новый aiogram требует
  `accepted_gift_types`. Три первоначальных падения тестов объяснялись именно
  неполной фикстурой; изменения бизнес-логики для их обхода не потребовались.

## Проверенные результаты

Среда: отдельная временная venv, Windows, CPython 3.12.14. Рабочая `.venv`
проекта на Python 3.13 и системные настройки не изменены. Для перехода на новый
набор нужно создать окружение по [инструкции](../../DEPENDENCIES.md); прежняя `.venv`
сама по себе не стала безопаснее после изменения lock-файлов.

| Проверка | Результат |
|---|---|
| Установка runtime + dev с `--require-hashes --only-binary=:all:` | Успешно; `pip check` без конфликтов |
| Повторная генерация трёх locks | SHA-256 файлов не изменились |
| Полный pytest на новом наборе зависимостей | 1071 passed, 0 failed; 20 subtests passed, 4169 warnings; 143,55 с |
| pip-audit 2.10.1, runtime + dev на Windows | 62 пакета, 0 известных уязвимостей, 0 пропусков |
| pip-audit, инструменты | 28 пакетов, 0 известных уязвимостей, 0 пропусков |
| Linux x86_64 / CPython 3.12 wheels | 57 runtime-пакетов установлены в отдельный target-каталог с проверкой хешей; cp312/manylinux tags подтверждены |
| pip-audit метаданных Linux wheels, включая uvloop | 57 пакетов, 0 известных уязвимостей, 0 пропусков |
| Изолированный demo seed | 86 тикетов, SQLite integrity_check: ok |
| Запуск uvicorn без Telegram и реальных credentials | `/healthz` и `/login`: HTTP 200; процесс после проверки остановлен |
| YAML CI и `git diff --check` | Успешно |

Результаты аудита действительны на 20 сентября 2026. Это проверка известных
уязвимостей зависимостей, а не гарантия отсутствия уязвимостей в приложении.
Linux wheels проверены как артефакты; Linux-код локально не исполнялся.
Предупреждения тестового прогона, включая прежние deprecation, этим этапом
не устранялись. Отдельный набор проверок runner: 23 unittest-теста прошли.

## Делегирование

Один вызов Claude Code, задача `release-dependencies-review`, роль
`security_reviewer`, read-only; три файла, 3588 байт исходного контекста,
одна попытка, ноль повторов. Claude рекомендовал locks и хеши. Lead проверил
выводы и уточнил ошибочное утверждение: ограничение aiohttp уже обеспечивалось
метаданными aiogram, а Python 3.12 уже был выбран Docker/CI. Сам аудит,
изменения и приёмка выполнены Lead. Решение записано в локальный журнал.
Runner также научен принимать точное имя `Dockerfile` без расширения;
прочие неизвестные файлы без расширения по-прежнему отклоняются.

## Следующий этап

1. Выполнить Linux/Docker/PostgreSQL jobs на итоговых изменениях. Здесь Docker
   daemon недоступен (`dockerDesktopLinuxEngine` отсутствует); запуск Desktop
   не завершился. Установки WSL, изменения служб или системных настроек не было.
2. Выбрать staging-сервер, собрать и сохранить digest образа, подключить
   домен/TLS, выполнить preflight и проверку восстановления резервной копии.
3. Проверить выделенный Fastmail mailbox: входящее письмо, ответ, вложение,
   сохранение цепочки. Затем проверить остальные выбранные каналы пилота.
4. После приёмки инфраструктуры подключить первую организацию и измерять
   использование, время ответа и трудозатраты на сопровождение.

Контейнер, PostgreSQL и удалённый CI этой локальной проверкой не подтверждены.
Прежние ограничения пилота из отчёта 17 сентября остаются актуальны.

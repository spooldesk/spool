## Исправления для запуска

1. Compose передаёт PostgreSQL host/user/database/password раздельно.
   `src/database/connection_url.py` собирает URL через SQLAlchemy, сохраняя
   специальные символы пароля. `DATABASE_URL` для обычных запусков по-прежнему
   поддерживается. `POSTGRES_HOST` явно включает раздельную конфигурацию и имеет
   приоритет; базовый SQLite Compose его сбрасывает.
2. `preflight.py --compose-file ...` проверяет итоговую среду dashboard после
   применения overlays. Ошибки Compose выводятся без его stdout/stderr, которые
   могут содержать пароли. Внешний PG через DATABASE_URL не требует отдельного
   POSTGRES_PASSWORD. Отдельный env-файл задаётся через SPOOLDESK_ENV_FILE;
   preflight устанавливает его только для своего subprocess.
3. Caddy ожидает healthy dashboard. Документация больше не утверждает, что
   Compose сам перезапускает unhealthy-контейнер: restart policy срабатывает
   при завершении процесса, а health status требует мониторинга.
4. Тесты и demo не наследуют POSTGRES_HOST из пользовательского окружения.
   Demo также удаляет остальные унаследованные PostgreSQL credentials.
5. CI дополнен запуском production image против PostgreSQL со сложным паролем
   и проверкой preflight по объединённой конфигурации Compose. Удалены устаревшие
   инструкции об отсутствии PG-миграций и достаточности изменения `.env` для
   переключения базового Compose на внешний PostgreSQL.

Проверка языка публичных инструкций теперь охватывает фактические файлы,
включая незакоммиченные изменения. Она не зависит от `.git` и не требует
переводить внутренние русскоязычные аудиты как пользовательскую документацию.

Пять пропусков PostgreSQL относятся к старому SQLite-bootstrap и его каталогу
PRAGMA; общие versioned migrations проверены на PostgreSQL. Предупреждения
deprecation этим этапом не устранены. После полного Linux-прогона дополнено
удаление унаследованных PG credentials в demo; целевые 33 теста на окончательном
варианте повторно прошли на Windows.

После восстановления тестовой PostgreSQL БД выполнен карантин из runbook:
незавершённые отправки переведены в `uncertain`, worker leases удалены.
Проверена только часть восстановления, относящаяся к БД. Вложения, ключи
шифрования, offsite storage и восстановление на новом сервере в эту проверку
не входили.

## Восстановление локального Docker

Docker Desktop 4.67.0 падал до запуска engine на двух служебных Unix-сокетах:
`dockerInference`, затем `docker-secrets-engine/engine.sock`. Это совпало с
[описанием сбоя в Docker issue tracker](https://github.com/docker/desktop-feedback/issues/460).
WSL уже был установлен и исправно запускался; устанавливать его не потребовалось.

После проверки содержимого сохранены только каталоги runtime-сокетов:

- `%LOCALAPPDATA%\Docker\run.stale-20260920-174149`;
- `%LOCALAPPDATA%\Docker\run.stale-20260920-174309`;
- `%LOCALAPPDATA%\docker-secrets-engine.stale-20260920-174309`.

Docker создал новые runtime-каталоги и запустил engine 29.3.1. Factory reset,
prune, удаление images/volumes/VHDX, обновление Docker, изменение системных
настроек и перезагрузка Windows не выполнялись. Старые socket-каталоги сохранены.

## Делегирование

Один read-only Claude Code worker, задача `release-compose-review`, пять файлов,
14071 байт исходного контекста, одна попытка, ноль повторов. Lead подтвердил
расхождение preflight с итоговым Compose и порядок запуска Caddy. Рекомендация
требовать POSTGRES_PASSWORD для любого внешнего PostgreSQL URL не принята:
credentials могут быть уже в URL. Пример `.env.example` также уже содержал
DATABASE_URL, чего worker не видел. Приёмка с оговорками записана в журнал.

## Что ещё нужно для пилота

Сервер, DNS и публичный HTTPS не проверены: VPS ещё не выбран. Не выполнены
живой Fastmail smoke, внешний мониторинг, offsite backup/restore на другом
сервере и проверка эксплуатационных процедур с ответственным оператором.

Следующий этап: выбрать staging VPS, развернуть проверенную версию, выполнить
preflight, проверить DNS/TLS, почтовую цепочку и восстановление данных.
GitHub Actions workflow изменён, но удалённый запуск на этих незакоммиченных
изменениях не выполнялся. Локальные результаты Linux не означают, что удалённый
workflow уже зелёный. Для публичного SaaS сохраняются ограничения из исходного
плана; текущая цель — управляемый пилот отдельного экземпляра.

# Walkthrough video

The narrated walkthrough on the landing (`docs/video/`) is generated by
`scripts/video/` from the static dashboard demo in `docs/demo/`, with fictional
data. When the dashboard changes visibly, re-record it rather than letting the
video drift from the product. A re-recording needs a browser and ffmpeg, not a
GPU: the narration is committed.

| File | Does | Writes |
| --- | --- | --- |
| `SCRIPT.md` | The script: scenes, English voice, Russian subtitles | — |
| `capture.py` | Films the demo with Playwright, one continuous session | `build/captures/` |
| `narrate.py` | Chatterbox voice per scene, checked by Whisper against the script | `narration/*.flac`, `report.json` |
| `cues.py` | Whisper word timings, so cuts and clicks land on the words | `narration/words.json` |
| `render.py` | Frames, cursor, music bed, subtitles; master and web copy | `build/export/`, `build/web/` |
| `timing.py` | Sentence boundaries and subtitle cutting (tested in `tests/test_video_pipeline.py`) | — |

`scripts/video/narration/` is committed: twelve 24-bit FLAC files (about
4.5 MB), the Whisper check and the word timings. `scripts/video/build/` is
ignored; only the finished web copy is kept, in `docs/video/`.

## Environments

None of this is in `requirements*.txt` or committed; the application and CI do
not need it.

- **Capture:** the development virtual environment plus
  `pip install -r requirements-screenshots.txt` and `playwright install chromium`.
- **Voice and render:** a separate virtual environment with PyTorch and
  torchaudio 2.6 (CUDA 12.6 build), `chatterbox-tts` 0.1.7, `faster-whisper`
  1.2.1, `pyloudnorm`, `soundfile`, `numpy` and Pillow, on Python 3.13. Only
  `narrate.py` needs a CUDA GPU (an 8 GB RTX 4060 is enough); `cues.py` and
  `render.py` run on the CPU. The Chatterbox and Whisper `small.en` models
  download into `HF_HOME` on first use; set it so they stay out of the user
  profile. On the maintainer's machine the environment is
  `E:\spooldesk-tools\tts-venv` with `HF_HOME=E:\spooldesk-tools\hf-cache`.
- **ffmpeg** on `PATH`, or `FFMPEG` set to the executable.
- **Segoe UI** for the text on screen, from the Windows fonts folder. Elsewhere,
  set `VIDEO_FONTS` to a folder holding `segoeui.ttf`, `seguisb.ttf`,
  `segoeuib.ttf` and `seguisym.ttf`.

## Re-recording

From the repository root, in this order (`$PY` is the voice environment's
Python):

1. **Capture.** `python scripts/video/capture.py` serves `docs/` on a free
   local port itself and films it. To film a server you run, pass
   `--base http://localhost:8020`.
2. **Narrate, then cues, only when the script changes.** Edit `SCENES` in
   `narrate.py`, the Russian lines in `render.py` and the table in `SCRIPT.md`
   together, then run `$PY scripts/video/narrate.py` (or `--only agent reports`
   for some scenes) and `$PY scripts/video/cues.py`. Every scene must score at
   least 0.95 in `narration/report.json`; `render.py` refuses anything lower.
   Nobody can judge the voice from a score, so listen to the changed scenes.
3. **Preview.** `$PY scripts/video/render.py --preview` writes the audio, the
   subtitles, `build/preview/*.jpg` and `build/export/Storyboard.jpg`. Look at
   the storyboard before spending minutes on frames.
4. **Render.** `$PY scripts/video/render.py` writes the master
   (`build/export/Spooldesk-walkthrough-EN.mp4`, CRF 18, for YouTube with the
   `.srt` files), then the web copy in `build/web/`: re-encoded with
   `-preset slow -tune animation -crf 23` and 128 kbit/s AAC, a 1280×720
   poster and the WebVTT subtitles, under the landing's file names. It stops if
   the MP4 is 25 MiB or more, which Cloudflare Pages refuses; the current one is
   about 12 MiB.
5. **Publish.** Copy `scripts/video/build/web/*` into `docs/video/`, run
   `python scripts/build_landing.py --check --export <new directory>` and the
   tests, and play the result on both landing pages.

## When things move

- **The dashboard changed.** `capture.py` records the boxes of the elements the
  cursor visits, so a moved button is still clicked. The camera framings in
  `render.py` (`HEADER`, `COMPOSER` and the zoom targets in each `s_*` scene)
  are fixed capture pixels; check the storyboard and adjust those. Selectors in
  `capture.py` follow the demo's English labels.
- **Whisper heard it differently.** Word timings are reproducible for the same
  audio, but any change to the audio, even rounding, moves them by a few
  hundredths of a second and can change spelling: it once heard "Spool Desk",
  which leaves the outro without its second "spooldesk". `render.py` then stops
  with the scene and the word it could not find; change the cue word there.
  The committed `words.json` was transcribed from the float audio before it was
  stored as FLAC, so do not re-run `cues.py` without new narration.
- **The clock.** The sent reply and the note show the time of the capture.

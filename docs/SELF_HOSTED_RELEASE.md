# Self-hosted: текущая модель выпуска

Решение от 2026-10-01: Spooldesk поставляется для установки на инфраструктуре
клиента, одна организация на экземпляр. Собственный VPS автора для этого не
обязателен. Команды внутри портала — маршрутизация, а не изоляция арендаторов SaaS.

## Что предлагается

| Вариант | Содержание |
|---|---|
| Self-hosted, $0 | Собственная установка в пределах действующей BSL и Additional Use Grant. Инфраструктура и внешние API оплачиваются отдельно. |
| Помощь с установкой, ориентир от $300 | Разовое согласованное внедрение; сроки, доступы, объём и приёмка фиксируются до оплаты. |
| Сопровождение, ориентир от $149/месяц | Обновления и помощь в согласованном объёме. Это не круглосуточный SLA по умолчанию. |
| Связаться с отделом продаж | Уточнить требования, инфраструктуру, интеграции и границы работ через hello@spooldesk.net. Нет автоматического оформления заказа. |

Платные услуги пока готовятся к запуску. Цены на лендинге ориентировочные,
не заменяют договор, реквизиты и налоговые условия. Hosted SaaS, неограниченный
MSP/reseller или white-label пакет не обещаются. Текущая BSL — source-available,
не OSI open-source лицензия; права определяет [LICENSE](../LICENSE).

## Состояние приёмки

- Пользователь сообщил, что ручные функциональные тесты выполнены. Это сообщение
  о ручной приёмке, а не автоматически сформированный протокол каждого канала.
- Предыдущий rc.3 прошёл полные Windows/PostgreSQL тесты, проверку image startup,
  backup/restore и аудит Python зависимостей. Точные результаты хранятся в пакете.
- Изменения лендинга, инструкции установки и упаковки получают новый кандидат;
  неизменный код приложения сверяется по SHA-256. Повторные и унаследованные
  проверки разделены в `VALIDATION.json`, а не объявлены новым полным прогоном.
- **Установка пользователем на другом компьютере ожидается.** Инструкция:
  [SECOND_COMPUTER_INSTALL.md](SECOND_COMPUTER_INSTALL.md).
- 2026-10-02 пользователь разрешил публикацию кандидата на GitHub для установки
  на втором компьютере. Это prerelease с явно незакрытой ручной приёмкой.
  Приватность репозитория сохраняется. Публикация сайта и registry-образа —
  отдельные действия. Старый локальный rc.4 не является опубликованным Git-тегом.

## До публичного программного релиза

1. Закрыть установочную приёмку на другом компьютере: чистый вход, обращение,
   вложение, сохранение после перезапуска.
2. Проверить состав исходников и права на них, лицензии включённых зависимостей
   и assets, отсутствие секретов. Один pip-audit не проверяет лицензионные права.
3. Зафиксировать прошедшую review ревизию, выполнить CI на ней и выпустить
   версионированные исходники/образ с checksums и ограничениями. Не выдавать
   текущую ветку `main` или непроверенный `latest` за принятый кандидат.

## До первого платного клиента

- Оформление деятельности и договорные условия: [LEGAL_READINESS.md](LEGAL_READINESS.md).
- Согласованный объём установки/сопровождения, оплата внешних сервисов, часы
  ответа, обновления и границы доступа к клиентским данным.
- Клиентский домен/HTTPS, независимые ключи и учётные записи, отдельный backup,
  проверка восстановления, внешний мониторинг и понятный ответственный.
- Проверка каналов и AI на выбранных аккаунтах клиента. Доступность ноутбука
  для домашнего теста не является обещанием постоянной доступности клиенту.

Отдельная staging-машина не является обязательной покупкой для первого
self-hosted выпуска. Изолированная тестовая установка нужна для безопасной
проверки изменений; разделение веток Git само по себе не создаёт такую среду.
